# client/specs

In-flight design docs for `@devdigest/web` — proposed changes, RFCs, and
course-lesson feature specs, written before implementation. Once a spec
ships, either delete it or mark it done at the top so it doesn't silently
drift from the code.

A spec whose own goals require changes in more than one package (e.g.
`server/` + `client/`, or a shared `@devdigest/shared` contract) belongs in
the top-level [`specs/`](../../specs/README.md) instead — not here.
