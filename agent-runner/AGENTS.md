# agent-runner — `@devdigest/agent-runner`

CLI that runs inside a TARGET repo's own GitHub Actions workflow (not this
repo's CI) to review a real pull request. Generated by the Export to CI
wizard (SPEC-05); full picture (wizard, security model, CI-run ingestion):
[../docs/export-to-ci.md](../docs/export-to-ci.md).

## Stack

TypeScript, ESM, `zod`, `yaml`. No workspace tooling (per root
`AGENTS.md`'s package convention) — own `package.json`/lockfile. Consumes
`reviewer-core/src` via a tsconfig path alias
(`@devdigest/reviewer-core` → `../reviewer-core/src`, `tsconfig.json`'s
`paths`), exactly like `server/` does — never reimplement or vendor review
logic. No shell/subprocess anywhere in this package; all PR content reaches
it via `fetch` or file reads.

## Run / test

- `npm run dev` — run `src/cli.ts` directly via `tsx`, outside any real
  GitHub Actions environment (useful with env vars faked by hand or in a
  test fixture)
- `npm test` (vitest) — hermetic: stubbed `LLMProvider`, GitHub-event JSON
  fixtures, no network
- `npm run typecheck`
- `npm run build` — `@vercel/ncc` bundles `src/cli.ts` into `dist/`

## Map

- `src/cli.ts` — entrypoint; reads config from env vars only (never CLI
  flags), so the generated workflow YAML never needs shell-escaping
- `src/github-context.ts` — reads the `pull_request` event payload, fork-PR
  detection, PR diff/comment fetch via plain `fetch` against GitHub's REST
  API (no `octokit`)
- `src/run.ts` — orchestration: assembles `reviewPullRequest`'s inputs,
  wraps branch name/comments as untrusted data, decides whether to post
- `src/result.ts` — builds `devdigest-result.json`, the exit code (via
  `reviewer-core`'s `countBlockers` — never a local reimplementation), and
  `redactSecret`

## Do-not-touch

- `dist/` is a committed `@vercel/ncc` build output — never gitignore or
  hand-edit it; it must match `src/`. The generated workflow's second
  `actions/checkout` pins to a commit SHA of *this* repo baked in at export
  time and runs this committed `dist/` directly; re-running Install
  regenerates the pin (see root `AGENTS.md`'s do-not-touch note and
  `../docs/export-to-ci.md`).

## Gotchas

- This package is consumed entirely inside a *different* repo's CI run — it
  never talks to this repo's own `server`/DB. Its only "API client" is
  GitHub's REST API, authenticated with the target workflow's own
  `GITHUB_TOKEN`.
- `OPENROUTER_API_KEY` is read once, handed straight to the LLM provider
  constructor; `redactSecret` exists only to guard output (errors/logs), not
  to gate the read itself.
